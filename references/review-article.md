# 综述成文 · 配置清单与失败模式

> 本文是 SKILL.md 的纵深。**动笔前读第一节，定稿前读第二、三节。**

---

## 一、先认领名头：三种综述的配置清单

**动笔前勾一个。勾完就知道自己要写哪些节。**

### A. 叙述性综述（Narrative Review）

**你在立一个论点。** 不强求穷尽。

| 必须 | 建议 |
|---|---|
| 一节「**方法与范围**」（检索来源 + 时间范围 + 纳排 + 去重 —— 一段话即可） | 用**主题式**或**论证式**结构 |
| 「**局限**」节 | 证据等级表 |

> ⚠️ 很多叙述性综述连「方法与范围」都不写——**能写就写**。
> 实测：同一份稿子，补上这一段之后就从「审稿人会追问」变成「可交付」。

### B. 系统综述（Systematic Review）

**你在回答一个可穷尽的问题。** 方法学透明性是**门槛**，不是加分项。

| 必须 |
|---|
| 检索策略（库 + 检索式 + 时间截止） |
| 纳排标准（逐条可操作） |
| PRISMA 流程图（识别 → 筛除 → 纳入，含每步数字） |
| 质量评价方法（用哪套工具，如 RoB 2 / NOS） |
| 去重与筛选流程（几人、分歧怎么解） |
| 注册号（PROSPERO）——**没注册会被问** |

### C. 范围综述（Scoping Review）

**你在绘地图。** 不做结论性判断。

| 必须 |
|---|
| 检索策略 + 纳排标准 |
| PRISMA-ScR 流程图 |
| **明确说明「本综述不评价证据质量，不给出推荐」** |

> ⚠️ 范围综述最常见的越界：**结尾下结论、给临床建议**。
> 那不是范围综述该干的——要下结论就去做系统综述。

> **名头拿不准 → 写叙述性。**

## 二、失败模式表（**来自一份真稿的核稿报告**）

2026-08-08，一份《精神分裂症患者体重管理及代谢干预》整合综述被按「投稿级审稿人 + 方法学核查」评审，
点出 3 项高优先 + 5 项中优先。**这些都是会重复出现的**——照表自查。

### 高优先（投稿前必修）

| # | 失败模式 | 怎么发现的 | 处置 |
|---|---|---|---|
| 1 | **标题自称「系统综述」，全文零方法学透明性** | 无检索策略 / 无纳排 / 无质量评价 → PRISMA 视角全缺 | 补方法节，**或**把名头降为「叙述性整合综述」 |
| 2 | **参考文献表不完整**——正文说「部分未列出的文献如 Kim 2007…在相应位置引用」，可**正文根本没给出处** | 正文引用 ↔ 表内条目**双向**核对 | 补入编号表 + 删掉自相矛盾的说明句 → 固化为**核查第四件套**（`check_ref_citations.py`） |
| 3 | **同一编号两处数据打架** | 2.3 节写「100 项 RCT、25 952 例 [14]」，4.2 节写「95 项研究 [14]」；而 [14] 是另一篇 | 核实数字出处——**极可能是另一个研究的数字被误标了编号**。人工回核 |

### 中优先（建议改进）

| # | 失败模式 | 处置 |
|---|---|---|
| 4 | **厂商数据当核心证据**——「显著减重但头对头未达优」全靠公司发布 | 补同行评议版本，或**弱化措辞 + 标「厂商公布数据」** |
| 5 | **正文零表格 / 图** | 数据密集处（减重等级、患病率）补 2–3 张汇总表 |
| 6 | **跨领域证据迁移没写边界**——[65][66] 都是肥胖/代谢人群 | 正文明确写「**双/三靶点精神科证据 = 肥胖人群迁移，需精神科专项试验**」 |
| 7 | **摘要偏长且非结构式**（~450 字一段） | 改结构式，或压到 250 字内 |
| 8 | 引言连引两篇核心文献却无铺垫 | 加半句「这两项是本领域的标志性证据」 |

### 通病（不在那份报告里，但最常见）

| 失败模式 | 自检 |
|---|---|
| **文献罗列** | 把框架拿掉，剩下是不是一堆摘要？ |
| **只引支持自己的** | 反证在哪一段？ |
| **每段首句是「XX 等（年）发现」** | 首句应是**论断** |
| **「整合讨论」退化成复述** | 它该写：证据全景 / 共同局限 / 未来方向 |

## 三、定稿自检九问

定稿前逐条问。**答不出「是」的，就是还没定稿。**

1. **名头与配置自洽吗？** 自称系统综述 → 检索策略在不在？（机检 R1）
2. **框架拿掉还剩什么？** 剩一堆摘要 → 重写结构。
3. **每段第一句是论断还是「XX 等发现」？**
4. **反证写了吗？** 有没有正面处理矛盾？
5. **每一段的论断能指回证据表哪一行？**
6. **正文引用 ↔ 文末编号表** 双向齐吗？（`check_ref_citations.py`）
7. **同一个编号在不同位置的说法一致吗？**（人工——机检查不了语义）
8. **厂商数据 / 跨领域迁移 / 未获取全文** 处，都标了吗？（机检 R2 只报数）
9. **摘要**是结构式，还是压到了 250 字内？

## 四、接口：上游与下游

| 方向 | 谁 | 交什么 |
|---|---|---|
| **上游** | `literature-pipeline` | 证据表（12 列）+ 覆盖声明 `N → M → K` |
| **本 skill** | —— | 综述初稿 → 定稿 |
| **下游** | `citation-reviewer` | 引用格式（GB/T 7714）、删改、去 AI 味、配图、上标 |
| **旁路** | `ai-academic-writing` | 表达层 / 内容层的机检工具（不在这里重复） |

> ⚠️ **别把下游的活提前干**——先保证「论点站得住」，再去做「句子好不好看」。
> 顺序反了，会在错的结构上抛一百遍光。
